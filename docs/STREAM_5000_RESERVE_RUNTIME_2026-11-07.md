## Bounded source implementation

The existing HTTP client now has control-specific raw-envelope methods with
exact string `"0"` status, one attempt, cancellation and bounded deadlines.
The original unwrapped methods and ordinary GET retry policy are preserved.
Successful legacy data is never rewrapped with an invented success code.
ACK acceptance remains distinct from independent applied configuration.

Installation ownership accepts a versioned, bounded recovery journal. Active
and unknown persisted claims recover as **held unknown**, without replay;
claim numbers remain monotonic. Conflicting installation keys cannot create
two active claims for one native command target. This consistency check does
not discover or authenticate the installation's real alias mapping.

An injected async reserve-pilot runtime remains default disabled and unbound:
no app/device/API registration, runner, qualification records or control cards.
It composes the reviewed pilot with durable intent barriers, owned phase
deadlines, serialized post-ACK selective readback and cancellation/late-callback
fences. Atomic journal storage, current native authority/provenance and shared
installation binding must be qualified before live integration. A mocked CAS
store is not proof Homey settings provide durable atomic CAS.

The runtime is intentionally one-operation-per-instance, with no queue or
automatic reuse after restoration. Its conservative journal blocks restart
replay rather than reconstructing a phase. Persistent terminal frontier and an
always-on independently authoritative admission provider remain unbound; an
in-process adapter-object storage fence is not distributed persistence proof.

The corrected runtime **retains its durable recovery obligation even after
successfully confirmed restoration** (`recoveryObligation: 'held'`). It never
clears that journal or releases its owner claim. A fresh runtime over the same
durable domain therefore also refuses admission. `restored` means selectively
confirmed configuration, not physical enforcement, durable closure or reopened
control. Separately qualified manual reconciliation/completion is still
unimplemented. This conservative availability restriction fixes the reproduced
failure where final context validation could fail after an empty-journal CAS.

Correlated negative ACK after a prior positive ACK now retains unknown during
the same active phase; identical positives and unrelated replies remain
harmless. A retired terminal pilot must not regain authority over a successor.
An independently authoritative observation/revocation provider must continue
governing admission; immutable old command objects are not that observer.

The operational pilot is still only 50 -> 51 / separately approved conditional
