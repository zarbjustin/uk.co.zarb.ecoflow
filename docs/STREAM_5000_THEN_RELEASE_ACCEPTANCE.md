# STREAM 5000 reserve THEN release acceptance

This is a separate, currently OPEN qualification scope. Monitoring acceptance
explicitly excludes new controls; it cannot qualify EdNL's battery THEN request.
This strong applied-control scope remains unbound. The separately owner-approved
[experimental request-only reserve card](STREAM_5000_REQUEST_ONLY_RESERVE.md)
does not qualify these gates or claim confirmed/restored control. No installed
runtime or store publication follows from adding that source-only card.

`npm run release:check` validates this ledger structurally and reports pending
gates. `npm run release:then` fails closed until every required gate passes for
both models. `npm run release:then -- --model es21` selects ES21 unit reserve
only; it never qualifies ES22, system control or another action.

`npm run release:full` also requires this reserve THEN evidence for both models,
alongside the existing Dual CT, monitoring and engineering checks. Missing THEN
assessment fails closed; monitoring acceptance cannot substitute for controls.

The ledger records independently reviewed claims with local provenance retained
privately. Its validator cannot generate native guarantees or independently
authenticate evidence. A manually edited "passed" label is not qualification.
Passed evidence must describe one exact runtime fingerprint and one exact
firmware version per model. References point to the criteria below; sanitized
qualification receipts must be attached here before signoff. No current receipt
qualifies any gate.

Scope excludes mode/feed/socket actions, exact watts, native return and system
controls. Their documented vocabulary is not action acceptance. A lasting
one-way request can have a distinct reviewed policy; it must not silently inherit
these strong applied-control claims. A fixed 50 -> 51 -> 50 demonstration is not
a vendor requirement or a universal prerequisite for every possible action.

## Identity scope

Qualify the exact model, firmware, installation and physical unit/main tuple,
consent and affected scope. Preserve private identities outside the public
ledger; do not infer unit scope from aggregate fields or a matching value.

## Native contract

Qualify causal application, bounded execution and terminal/no-late disposition
or a documented, independently reviewed equivalent. ACK plus matching readback
and a finite quiet period do not prove these properties. Local revisions cannot
be presented as native revisions. A local stop does not cancel a vendor request.

## Private durable cas

Qualify actual private storage, committed durability, exact incarnation/revision
CAS, ambiguous acknowledgement, anti-rollback recovery and ownership retention.
An in-memory fake, ordinary settings write or public userdata file is not proof.

## Issuance fencing

Qualify commit-before-possible-submission, one issuer, old-process fencing and
uncertain-dispatch holds. No automatic transport retry, reconnect replay or
automatic inverse; fencing local work cannot revoke already submitted work.

## Driver binding

Review the actual device-scoped handler, immutable action arguments, serialization
and provider integration. Current unbound source engines do not pass this gate.
Preserve saved cards, existing drivers and native-AI ownership.

## Exact runtime

Verify exact candidate installation non-clean under precise owner approval and
its runtime identity. Source push, CI, an old installed app or version equality
alone does not establish this candidate's installation.

## Action readback

Validate the precisely approved action on an eligible baseline with qualified,
field-specific receipt and causal correlation. Keep accepted request, observed
configuration and physical outcome distinct. Do not enable reserve or alter
settings to manufacture eligibility.

## Native ai preservation

Verify the approved native-AI conflict/ownership policy, adjacent configuration,
devices, Flows, Insights, cumulative counters, Energy roles and system scope.
Read-only identity preservation is useful but not proof of battery preservation
after an action. No occupied-household competing-writer fault experiment.

## Recovery

Review loss/timeout/restart/recovery and cancellation semantics on the actual
providers. Retain uncertain claims and quarantine; do not infer no late action
from local expiry or repeated equal observations.

## Ui semantics

Validate actual Homey/browser/native presentation and error behavior. "Requested",
"observed applied" and "physical outcome" cannot be conflated. Dependent Flows
must not treat unknown submission as applied success.

## Normal use soak

Complete at least 48 continuous hours on the exact runtime/firmware/action scope,
with the approved preservation/readback cadence and no disqualifying change.
Start/end timestamps are necessary but not sufficient: the validator does not
prove observation coverage or manufacture a physical pass.
